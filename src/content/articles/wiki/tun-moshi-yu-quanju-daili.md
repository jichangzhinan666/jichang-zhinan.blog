“开了代理为什么游戏不走？”“开了全局为什么国内网站变慢？”这两个高频问题的根源是把两组概念混在了一起。本文把它们拆开：一组决定**哪些流量被客户端拿到手**，另一组决定**拿到手的流量往哪送**。

## 第一组：接管方式——系统代理 vs TUN 模式

### 系统代理（System Proxy）

客户端在操作系统里登记一个 HTTP / SOCKS 代理地址（例如 127.0.0.1 加某个端口）。浏览器等**遵守系统代理设置**的程序会把请求交给这个地址。

- 优点：设置简单，无需管理员权限，兼容性好，开关迅速。
- 缺点：不遵守系统代理的程序（多数游戏、命令行工具、部分桌面客户端、Windows 商店应用）完全不受影响；UDP 流量通常不经代理。

### TUN 模式

客户端创建一块虚拟网卡，并把系统默认路由指向它，于是**所有 IP 流量**（TCP 与 UDP）都先经过客户端，再由客户端决定去向。

- 优点：覆盖全部程序，包括游戏、命令行、不读代理设置的软件；支持 UDP；可以接管 DNS，减少 DNS 泄露（见[DNS 泄露排查](/tutorials/dns-xielou-jiance-paicha/)）。
- 缺点：需要更高权限（Windows 上要安装服务，macOS 要授权）；配置不当时会影响局域网访问；多开一层处理，对老旧设备有一点性能开销。

两者通常二选一。开启 TUN 后再开系统代理没有意义，部分客户端会自动处理。

## 第二组：去向规则——规则 / 全局 / 直连

无论用哪种接管方式，客户端拿到流量后都要决定往哪送：

- **规则模式（Rule）**：按订阅里的规则逐条匹配：国内域名与 IP 直连，海外域名走选定节点，广告域名拦截等。日常使用的默认选择。
- **全局模式（Global）**：不看规则，全部流量走当前节点。国内网站也要绕一圈海外，变慢且可能触发“异地登录”提醒。只适合排查“是不是规则把某个网站判错了”。
- **直连模式（Direct）**：全部不走代理，等于临时关闭。

“全局代理”这个词在日常口语里常被用来指“TUN 模式”，但在 Clash 系客户端的界面里它明确是去向模式之一。本文标题中的“全局代理”即指这一含义。

## 组合与推荐

| 接管方式 | 去向 | 适合 |
| --- | --- | --- |
| 系统代理 | 规则 | 桌面端日常上网、新手 |
| TUN | 规则 | 游戏、命令行工具、所有应用都需走代理、减少 DNS 泄露 |
| 系统代理 / TUN | 全局 | 临时排查规则问题 |
| 任意 | 直连 | 临时关闭代理 |

不推荐长期使用全局模式。

## 手机与官方客户端对应什么

- **iOS**：所有代理客户端通过系统 Network Extension（VPN 配置）工作，等同于 TUN 模式。用户只需选择路由模式（按配置分流 / 全局 / 直连），见[iOS 教程](/tutorials/ios-shiyong-jiaocheng/)。
- **Android**：客户端通过 VpnService 接管流量，同样等同于 TUN。多了一个“分应用代理”，可以让指定 App 不进隧道，见[Android 教程](/tutorials/android-shiyong-jiaocheng/)。
- **机场官方客户端**：通常默认以 TUN / VPN 方式接管并内置规则分流。例如隐形人与灵动云的站长实测报告中，客户端版本标注为“V3.0.0（智能分流）”——“智能分流”对应的就是规则模式。官方客户端一般不让用户编辑规则，这是它比第三方客户端简单、也比第三方客户端受限的原因。

## 常见问题的归因

- **游戏不走代理**：接管方式是系统代理，游戏不读代理设置 → 改用 TUN。
- **国内网站变慢 / 异地登录**：去向模式是全局 → 改为规则。
- **TUN 开不了**：权限或服务未安装 → Windows 安装服务并以管理员运行，macOS 授权。
- **局域网设备连不上**：TUN 接管了局域网段 → 检查 fake-ip 过滤或局域网直连规则。
- **开 TUN 后 DNS 检测结果变了**：TUN 接管了 DNS，这是预期行为。

更多排错见[常见客户端问题](/tutorials/windows-kehuduan-changjian-wenti/)。

## 一句话记忆

**系统代理 / TUN 决定“谁被拿到手”，规则 / 全局 / 直连决定“拿到手往哪送”。** 日常用“系统代理 + 规则”，需要覆盖全部程序时用“TUN + 规则”，全局只用来排错。
